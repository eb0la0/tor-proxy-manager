## [2.0] — 2026-08-08

Главное в этой версии: **GitHub перестал быть единственной точкой отказа при
получении мостов**, а интерфейс переработан в компактный dashboard.

### Исправлено: источники мостов были мертвы

Проверка 2026-08-08 показала, что **11 из 15 URL-адресов источников
отдавали 404**:

| Репозиторий | Состояние |
|---|---|
| `Delta-Kronecker/Tor-Bridges-Collector` (оба «приоритетных» источника) | удалён |
| `Ckid-Home/tor-bridges`, `miguelneto0/…`, `miladtorrent/…`, `nicktacular/…` | 404 |
| `scriptzteam/Tor-Bridges-Collector` | работал, но отставал на 10 дней |

Фактически приложение держалось на одном устаревшем списке с GitHub и никак
об этом не сообщало.

### Добавлено

- **Многоисточниковая загрузка с автоматическим fallback.** Источники
  опрашиваются параллельно (общий дедлайн 60 с), сливаются строго по
  приоритету — результат детерминирован и не зависит от того, кто ответил
  первым.
- **Разделение «источник» и «зеркало».** Зеркала одного источника содержат
  одни и те же данные и перебираются по очереди до первого успеха; не-GitHub
  зеркала стоят первыми. Это и есть обход блокировки GitHub.
- **Реестр источников** `core/bridge_sources.py`: новый источник добавляется
  одной записью, остальной код не меняется.
- **Кеш последнего рабочего набора** `core/bridge_cache.py`: версионированный
  формат, атомарная запись, тип моста и время обновления.
- **Окно диагностики**: состояние каждого поставщика, хост, задержка, причина
  отказа, число отклонённых строк.
- **Тесты**: 96 unit-тестов на stdlib `unittest`, без сети и новых
  зависимостей.

### Исправленные ошибки

- **Кеш затирался пустым результатом.** Неудачное обновление записывало пустой
  список поверх рабочих мостов — ровно сценарий «вчера мосты были, сегодня
  GitHub недоступен, мостов нет». Пустой результат больше не сохраняется.
- **Тип моста мог быть повреждён.** Если переключить транспорт во время
  обновления, результат сохранялся под чужим типом: obfs4-мосты помечались как
  webtunnel и становились активными. Тип фиксируется на всё время обновления.
- **`HTTP 200` с HTML-страницей считался успешной загрузкой.** Добавлены
  проверки `Content-Type`, размера ответа, признаков HTML и запрет межхостовых
  редиректов.
- **Полный отказ сети не считался ошибкой** — пользователь видел «0 мостов»
  без объяснения. Теперь «0 мостов» — четыре разных состояния с разными
  сообщениями: не ответил никто / ответили мусором / источники пусты /
  мосты получены, но недоступны по сети.
- **`NameError` в автозапуске Windows.** Ключ в реестр записывался, затем
  функция падала на логировании и возвращала «ошибка». Плюс в режиме запуска
  из исходников регистрировался голый `python.exe` без пути к скрипту.
- **Приложение падало при выходе во время обновления** — рабочие потоки
  уничтожались на ходу. Завершение ограничено по времени и безопасно.
- **Ошибка тестировщика уничтожала рабочий набор мостов.**
- **Случайная выборка обесценивала приоритет источников.** Из тысяч мостов
  тестировались 250 случайных, и у курируемых был шанс ~5 %. Теперь 60 %
  выборки берётся с головы приоритетного списка.
- **Кеш версии из будущего** больше не интерпретируется молча.

### Интерфейс

- Переработан в **dashboard**: герой со статусом Tor во всю ширину, «Мосты» и
  «Приложения» в две колонки (на узком окне складываются в одну), компактная
  «Активность». Окно по умолчанию 940×660 — всё видно без прокрутки.
- **Design-система** `gui/theme.py`: уровни поверхностей вместо рамок вокруг
  каждого блока, единая шкала отступов, радиусов и типографики.
- **Иконки рисуются кодом** (`gui/icons.py`) — без иконочных шрифтов и новых
  зависимостей, чёткие на HiDPI.
- **Контраст приведён к WCAG AA** (минимум 4.31:1); добавлены состояния
  фокуса для навигации с клавиатуры.
- **Состояние источников** видно на главном экране одной строкой
  («Источники: 3/4»), подробности — в окне диагностики.
- **Работа на сохранённых мостах** явно обозначается, вместо «08.08 05:09»
  показывается «обновлены 5 минут назад».
- Все строки интерфейса переведены; каталоги RU и EN синхронны.

### Важное уточнение о независимости источников

Шесть списков — это **четыре независимых поставщика**, а не шесть точек
отказа: «проверенный» и «полный» списки одного репозитория недоступны
одновременно. Поэтому интерфейс показывает число поставщиков.

Сами мосты у поставщиков в основном совпадают (замер для obfs4: 99.5 % мостов
igareck присутствуют и в scriptzteam-v1). Ценность нескольких источников —
не в разных мостах, а в **независимых каналах доставки**.

### Известные ограничения

- При одновременной блокировке GitHub и githack остаётся один поставщик
  (igareck) с его не-GitHub зеркалами.
- Доступность источников проверялась из окружения разработки и не является
  доказательством доступности из РФ.
